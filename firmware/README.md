# Минимальная прошивка

`main.c`: SDCC mcs51, 11,0592 МГц, UART 9600 8N1, LED P4.0 active-low,
walking-data/address signature/March C- по всем 32768 байтам XDATA.
Переменные и стек находятся во внутренней RAM, поэтому SRAM можно
проверять до доверия к ней. Прерывания отключены; таймер 1 — UART,
таймер 0 — интервалы мигания. АЦП тестовой программой не проверяется.

Сборка (Python 3 и SDCC 4.5):

```powershell
python firmware/build.py --sdcc "C:/path/to/sdcc.exe"
```

На Linux можно опустить `--sdcc`, если SDCC находится в PATH.
Результат: Intel HEX `build/retro535.ihx`, 64-КиБ CODE и полный 128-КиБ
образ SST39SF010A. Неиспользуемые байты равны FF; контрольные суммы рядом.
Начальная программа начинается с reset vector 0000h. Собирать в small model,
не переводить стек или служебные переменные в XDATA.

Бесплатная программная проверка — **µCsim s51** из комплекта SDCC:

```powershell
python firmware/simulate.py --s51 "C:/path/to/s51.exe"
```

Нужна предварительная сборка, включая `.map`. Скрипт выполняет два случая:
исправная идеальная SRAM и внесённая ошибка адреса 0000h. Проверяются UART
PASS/FAIL и записи FE/FF в SFR P4. Вывод и результаты — `../reports/sim-*`
и `firmware-simulation.json`. На использованном SDCC/µCsim 4.5 оба прошли.

Это модель инструкций **C52**, не точная модель Siemens SAB80535-N.
Она не проверяет физическую шину, тайминги Flash/SRAM, аналоговые входы,
порог сброса, USB, разводку, загрузочную способность или конкретный экземпляр
старого МК. Переключения SFR P4 проверяются как записи в регистр; реальное
мигание светодиода пока не испытано. Симуляция не заменяет прототип.

Сборка и перепрошивка снятой Flash описаны в `../docs/bring-up.md`.
USB-UART здесь — консоль, не программатор.

Источники инструментов: [SDCC](https://sdcc.sourceforge.net/),
[µCsim](https://ucsim.sourceforge.net/).
